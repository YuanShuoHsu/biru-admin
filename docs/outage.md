# 斷網與系統故障應變

門市斷網、Biru 系統故障或綠界故障時，店員照這份流程繼續營業。開幕前照[演練](#演練)實際做一次。

## 先判斷是哪一種

| 看到的情況                                                    | 情境                                 |
| ------------------------------------------------------------- | ------------------------------------ |
| 店內平板全部連不上，但店員手機關掉 Wi-Fi 用行動網路可以開前台 | [A. 門市網路斷線](#a-門市網路斷線)   |
| 店員手機用行動網路也開不了前台、後台                          | [B. Biru 系統故障](#b-biru-系統故障) |
| 系統能開，但付款頁失敗或發票一直開不出來                      | [C. 綠界故障](#c-綠界故障)           |
| 門市停電                                                      | [D. 停電](#d-停電)                   |

## A. 門市網路斷線

最常見的情況。Biru 的系統和資料庫都在雲端，所以門市斷網時，雲端照常運作，訂單、付款和電子發票都由雲端處理。只有店內的設備連不上。

| 受影響                                         | 不受影響                                         |
| ---------------------------------------------- | ------------------------------------------------ |
| 店內平板：後台、廚房出單畫面、取餐與叫號看板   | 用自己行動網路的顧客：掃碼點餐、付款、候位都照常 |
| 出單機（出單機向雲端主動取單，斷網就不會出單） | 電子發票的開立與上傳                             |
| 連店內 Wi-Fi 的顧客與點餐平板                  |                                                  |
| 員工打卡（打卡要求店內網路的 IP）              |                                                  |

處理：

1. 確認 4G 備援路由器已自動切到行動網路（燈號見設備說明）。切過去後，平板和出單機會自己恢復，不用重開。
2. 沒切過去：重開路由器；還是不行，店員手機開熱點，給吧台的平板連上，先恢復廚房出單畫面。
3. 請連店內 Wi-Fi 的顧客改用自己的行動網路點餐。
4. 斷網期間出單機漏掉的單，在後台廚房出單畫面確認，必要時重印。
5. 打卡：用 4G 備援時，對外 IP 會變，打卡會被擋。網路恢復後，由員工在後台送「補打卡」申請。
6. 打給網路業者報修。

## B. Biru 系統故障

雲端系統（Render 或 Supabase）無法使用，顧客和店員都無法點餐、看單。

1. 用手機的行動網路確認前台也打不開；打得開的話回到 A。
2. 在門口和桌上放「暫停掃碼點餐」告示，改由店員紙本點單。
3. 只收現金。用紙本點單本記錄：時間、桌號或取餐號、品項、金額、收款方式。
4. 發票：店員手機用行動網路登入綠界廠商後台，用「B2C 電子發票 > 發票新增作業（單筆開立）」逐筆開立，發票號碼寫在紙本點單上。
5. 已經在系統裡、但還沒出餐的訂單，照紙本或店員記憶先做完，恢復後在後台補上狀態。
6. 系統恢復後：
   - 這段期間的紙本銷售不在 Biru 報表裡，把紙本點單本與綠界後台開立的發票對帳後，交給記帳的人。
   - 這段期間沒有扣庫存，依紙本品項到後台做庫存調整。

## C. 綠界故障

1. 線上付款失敗：引導顧客到現金機付款。
2. 發票開立失敗時，訂單仍然會完成，發票停在待開立。綠界恢復後，到後台訂單用「補開發票」重試，或看綠界待處理清單。
3. 發票要在開立翌日起 2 日內上傳財政部（綠界代上傳）。綠界故障超過這個時限時，屬於不可歸責營業人的事由，要在事由消滅翌日起 3 日內向北區國稅局（桃園分局）申請補正時限，並保留綠界的故障公告截圖。

## D. 停電

1. 路由器與出單機會跟著斷電，平板靠自身電池，但連不上店內網路。冷藏冷凍設備照[門市例行檢查表](https://github.com/YuanShuoHsu/biru-api/issues/444)記錄溫度與停電時間。
2. 照 B 紙本營業（店員手機用行動網路開立發票），或暫停營業。系統裡的營業時間不用改，臨時停業用特殊營業日設定，讓系統通知受影響的訂單與候位。

## 演練

開幕前、之後每半年一次，在非營業時段：

1. 拔掉對外網路線，確認 4G 備援自動切換、平板和出單機自己恢復，記下切換花了多久。
2. 用一支手機下測試訂單，確認廚房出單畫面收到、出單機出單。
3. 照 B 用紙本點單本和綠界廠商後台各開一張測試發票（綠界測試環境）。
4. 把演練日期和發現的問題記在下面。
